## Causes and restoration

1. **Phantom stations:** Core accepted an address whenever *any* of Addr1/Addr2/Addr3 matched the selected AP. It ignored ToDS/FromDS, accepted group addresses and the AP itself, and did not refresh duplicate RSSI. The real extracted callback reproducer reports one client for a multicast downlink in original Core, and zero in both historical and repaired callbacks. The restored parser uses infrastructure DS direction, validates the corresponding BSSID field, excludes IBSS/WDS, multicast/broadcast, AP-self and zero addresses, and refreshes RSSI. Addr3 is not treated as station evidence. RSSI remains received-frame RSSI: downlink observations measure the AP transmitter, not the client receiver.
2. **Rejected Deauth frame type:** the validated lineage supplied `ieee80211_raw_frame_sanity_check` and the matching multiple-definition linker option. Core omitted both and called the stock ESP-IDF raw-TX path, whose documented frame set excludes Deauth. The historical hook/link behavior is restored and the final ELF disassembly verifies that `esp_wifi_80211_tx` calls the linked return-zero hook. This private driver ABI and broad historical hook require the pinned IDF/driver and hardware acceptance; a build is not an RF transmission measurement.
3. **UART Deauth stopped immediately:** Core forced UART inline, while its count-zero loop only continues on a worker. Executing the pre-patch adapter reproduces zero worker dispatches, one TX call, a released lease, and the misleading `Deauth started` response. Deauth now uses the existing worker and an adapter-owned persistent queue; acknowledgement is printed after ACCEPTED arrives. Pending STOP is remembered and applied when the token arrives. Other UART scans retain their synchronous behavior. The existing DEAUTH_PROGRESS event now reports successful driver TX calls per second and UART emits the historical `pkts/s` line; that is driver acceptance, not proof of peer disconnection. Current Core's per-frame pacing, target selection, channel checking, error return and ownership are retained; the old duplicate/disassociation burst implementation is not copied wholesale.
4. **Beacon absent:** Core dispatched all Beacon operations to UNSUPPORTED. Restored SSID/rate/channel beacon construction and channels 1–11 through the current service, HAL, arbiter and periodic task. One bounded frame per tick, session-lifetime SSID allocation, stable locally administered BSSIDs, family-checked status/stop, failure reporting and peer-reset/STOP_ALL cleanup. Open beacons do not falsely set a privacy bit. The capability overlay now agrees with implementation.
5. **Handshake stimulation absent:** UART always requested zero Deauth frames. It now requests the historical 3-second/20ms paced reconnect phase and 10-second capture window, repeating until stop/capture completion. Current EAPOL parsing, buffering, export, target filtering and terminal cleanup remain. Native/SPI explicit counts are finite and zero remains passive. TX runs from the existing periodic task, not the UART call or radio receive callback. Failure, STOP_ALL, successful capture and peer reset disarm further TX. The old extra duplicate frames, selected-station secondary burst and resetting captured data on each retry are not copied.
